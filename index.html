Shaders

Fragment shaders written for projection and live visuals. Each one comes as three files — one for TouchDesigner, one for Resolume and anything else that reads ISF, and one for a web page.

Download all four zip, 19 KB

Putting them to work

TouchDesigner

  1. Add a GLSL TOP.
  2. Open its Pixel Shader and paste the file in.
  3. On the TOP’s Vectors page add a uniform called uTime and point it at absTime.seconds.

Step three is not optional. Without a clock the shader compiles fine and renders one frozen frame, which looks like the shader is broken.

For the ones that follow the pointer, add a vec4 called uMouse and feed x and y from a Mouse In CHOP, normalised 0–1.

Resolume & other ISF hosts

Drop the .fs file into the host’s ISF folder and it turns up as a source.

Restart the host if it does not appear. Most of them only read the folder on launch.

Pointer-driven shaders expose a mouse point control in the host’s own interface, so you can put it on a MIDI knob.

A web page

GLSL ES 1.00, which is what WebGL1 takes and every browser runs without argument. Four uniforms:

  • iResolution vec3
  • iTime float
  • iMouse vec4
  • iFrame int

viewer.js in the repository is a working example of feeding them, and it is the same file running the pictures above.

How these are made

Each shader is written once, in the Shadertoy dialect, and tools/port.mjs puts the three collars on it. Nothing is hand-converted, so the TouchDesigner version cannot quietly drift away from the ISF one. If you want to change a shader, change the file in src/ and run the script.

Originals on Shadertoy. Everything here is in the repository.
